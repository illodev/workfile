# Workfile — Competitive Research Report

**Date:** 2026-08-01 · **Subject:** `@illodev/workfile` v0.2.0 · **Basis:** deep reads of four competitor repos (source, docs, live GitHub/npm API), plus measured verification against this checkout (75 cards, 6 ADRs) and the bench harness at S/M/L/XL.

Everything below marked **[deep read]** was read in the competitor's source or docs. **[measured]** was executed on this machine. **[inferred]** is judgement, not evidence.

---

## 1. The landscape

| Project | What it is | Distance from Workfile | Its one strongest idea |
|---|---|---|---|
| **[Backlog.md](https://github.com/MrLesk/Backlog.md)** — 6,339★, MIT, Bun/TS, v1.48.0, ships every 2–4 weeks | Markdown tasks with frontmatter in `backlog/`, git is the database, CLI + local kanban + MCP | **Direct competitor. Closest structural analogue that exists.** Independently arrived at nearly Workfile's domain split (tasks/docs/decisions/milestones/drafts) | Machine-owned body regions (`<!-- SECTION:PLAN:BEGIN -->`) + acceptance criteria and Definition-of-Done as **indexed, index-addressed** data, not prose |
| **[Beads](https://github.com/gastownhall/beads)** — 25.8k★, MIT, Go, `@beads/bd` 1.1.2, 24k npm downloads/mo | Version-controlled SQL (Dolt) as canonical, embedded at `.beads/embeddeddolt/`; CLI + MCP only | **Direct ideological opponent.** Same problem, inverted storage bet | Cell-level merge — two agents editing different fields of the same record merge automatically. Plus `bd gate` (typed self-resolving blockers) and `bd merge-slot` (named exclusive lease) |
| **[Task Master AI](https://github.com/eyaltoledano/claude-task-master)** — 27.9k★, MIT+Commons Clause, last push 2026-04-28 (~3 mo stale) | `.taskmaster/` + one `tasks.json`; PRD → model decomposition → task graph; MCP into Cursor/Windsurf/Roo | **Direct competitor, largest by adoption, weakest by architecture** | `parse-prd`: a document becomes a whole task tree in one command. That funnel is why it got adopted. Plus tiered MCP tool profiles with published token costs (7≈5k / 15≈10k / 36≈21k) |
| **[git-bug](https://github.com/git-bug/git-bug)** — 9,960★, GPL-3.0, Go, v0.10.1 after 8 years | Issues as git objects under `refs/`, operation-based CRDTs, explicitly "not files!" | **Adjacent.** Zero agent surface — no MCP, no instruction generation, no claims | A normative spec with RFC-2119 MUST language, separate reader/writer conformance checklists, and committed test vectors the test suite eats |

**Honest reading of the table.** "Markdown tasks in git for AI agents" is not differentiating in 2026 — Backlog.md owns it with 6.3k stars, two conference talks (Devoxx Belgium 2025, AI Engineer Code Summit 2025) and a third-party VS Code extension, which means its file format already became a platform. Beads is three orders of magnitude ahead on distribution and shipping faster than this project. Task Master is bigger than both and going stale. Workfile is v0.2.0.

Where they beat us, plainly:

- **Backlog.md**: structured AC/DoD, body-region protocol, ~1KB instruction stub vs our full managed blocks, cross-branch state resolution, shell completions, a TUI, distribution.
- **Beads**: automatic conflict resolution, collision-free hash IDs, graph-derived `bd ready`, select-and-claim in one op, compaction, gates, templates, distribution.
- **Task Master**: bulk ingestion, MCP tool tiering, a complexity dimension, `testStrategy` declared at planning time.
- **git-bug**: convergent merges with a proven ordering, and specification discipline we do not have.

**[inferred — not verified in this pass, leads only]** Adjacent-but-not-examined: [taskwarrior](https://github.com/GothenburgBitFactory/taskwarrior) (local task DB, no agent surface), [git-issue](https://github.com/dspinellis/git-issue) (shell, issues in git), [Fossil](https://fossil-scm.org) (SCM with built-in ticketing), [spec-kit](https://github.com/github/spec-kit) (spec-driven agent workflows in-repo). Treat these as unverified.

## 2. Where Workfile is genuinely differentiated

Five things, in descending order of defensibility. All are things a competitor would have to re-architect to match, not add.

| # | Differentiator | Evidence |
|---|---|---|
| 1 | **Claim granularity below the issue.** Claims are *scope paths*, refused on overlap at claim time (`CARD_SCOPE_OVERLAP`) and enforced at the mutation (`CARD_CLAIM_OWNER_MISMATCH`). | Beads claims an *issue* — two agents on different issues touching the same file collide silently, nothing in its docs detects it **[deep read]**. Backlog.md's entire concurrency answer is file locking around ID allocation plus the convention "one task = one context window = one PR" **[deep read: `scripts/smoke-parallel-task-locking.sh`]**. Neither has revision tokens or stale-write rejection. |
| 2 | **`doctor` as a 72-rule CI gate with a committed baseline.** `--new` exits non-zero only on issues that appeared since the baseline. | Backlog.md has **no validation command at all**, and its own repo pays for it: a 27KB `duplicate-task-repair.ts`, a `prefix-migration.ts`, and dangling dependency refs left behind by that migration **[deep read]**. Nobody else in the survey ships one. |
| 3 | **Four domains on one index.** History (changelog fragments consumed into releases, derived `CHANGELOG.md`) and typed Memory (LRN/ADR/INC/CONV/CTX with graduation, supersession, confidence, expiry). | No analogue anywhere. Beads' memory is `bd remember` — a flat string→string KV with auto-generated keys, no confidence, no typing, no supersession **[deep read]**. Beads has no History domain at all. |
| 4 | **Deterministic lexical grammar, identical across four surfaces.** `kind:`, `tag:`, `field:value`, negation, quoted phrases, regex mode. | Backlog.md is fuzzy-only with relevance ordering, and its CLI reference explicitly excludes scores from the stable contract **[deep read]**. Fuzzy is friendlier to type and impossible to reason about. |
| 5 | **Human-legible canonical storage, plus a byte-stable restricted-YAML codec** whose parser and serializer are declared exact inverses, preserving unknown fields and body bytes. | Beads' own FAQ says `.beads/issues.jsonl` is "a passive export, never the database" — so the only human-readable representation of the plan is disclaimed by its authors **[deep read]**. git-bug's records are git objects `grep` cannot see. Backlog.md uses full YAML (block sequences, quoted scalars, a datetime migration script), which forecloses byte-stable round-tripping permanently. |

Two smaller ones worth stating in the README because they are free: **plain MIT** (Task Master is MIT + Commons Clause; GitHub's API cannot resolve it to an SPDX identifier and reports license "Other" — that ambiguity is what makes legal teams say no), and **no network by default** (Task Master's `research` command injects project context into a third-party API; `models --set-main` requires an API key).

**Caveat that must be stated internally, not externally:** #1 and #2 are the positioning, and #1 is **partially false in the shipped default configuration today**. See §3 and §10.

## 3. Where Workfile is genuinely behind

### 3a. The differentiator is broken in three measured places

| Defect | Evidence | Severity |
|---|---|---|
| **Concurrent `card create` mints duplicate IDs.** The reservation `.project/.cache/locks/ids/<ID>.lock` is released in `finally` (`mutations.ts:~313`) immediately after `createFileExclusive(path)` — and `path` is `${id}-${slugify(title)}.md`. The lock protects the *ID*; the durable guard protects the *path*. Two different titles never collide. | **[measured]** 200 cards / 4 concurrent processes: 2 of 8 batches duplicated. 76 cards / 12 processes: 4 of 8 batches. 5,000 / 12: three duplicate pairs. Even the S fixture (50 cards) reproduced in 3 of 4 trials. Same shape in `docs.ts`, `memory.ts`, `changelog.ts`. | Breaks "collision-safe ID reservation" (README:652). Loud and recoverable (`doctor` + `renumber --duplicates`), but T-0019 asserts *in writing* that "same-checkout races are already handled." The repo carries a documented belief that this bug does not exist. |
| **Three actor identities per session that never match.** `defaultActor()` reads `CLAUDE_SESSION_ID` — **which does not exist**; Claude Code sets `CLAUDE_CODE_SESSION_ID`. **[measured: confirmed in this shell]** So CLI falls to `$USER@$HOSTNAME`, the hook compares a UUID, MCP derives `mcp:<clientName>`. Three call sites read the phantom var (`bin/workfile.ts:614`, `mcp/tools.ts:105`, `runtime/claude/hooks.mjs:126`). | **[measured]** Fed the real hook runtime a board where T-0099 is claimed by `illodev@local` and an edit in its scope: returned `permissionDecision: ask`. **The guard rail fires on your own claim, on the first card, in a single-agent session.** Conversely, two parallel Claude sessions resolve to the *same* `$USER@$HOSTNAME`, so `CARD_ALREADY_CLAIMED` never fires between them. | The README's "two agents in one checkout collide loudly" is false in both directions in the shipped default. This repo's own trail carries six hand-invented actor ids across 87 claims — `defaultActor()` is not merely broken, it is unused. |
| **`card release` and `card transition` omit the actor default.** `bin/workfile.ts:917` and `:933` pass `actor: option("--actor")` with no `\|\| defaultActor()`, unlike `note` (835), `claim` (899), `next` (1842). The guard is `claimed_by && actor && claimed_by !== actor && !force` — undefined actor ⇒ guard evaporates. | **[measured: confirmed at source]** The shipped plugin's `/done` runs `card transition $1 review` with no `--actor`. `--force` is in `GLOBAL_FLAGS` so it parses, but the transition branch never reads it. | Omitting a flag is a silent force, along the plugin's own primary path. `mutations.ts:514`'s comment says the transition guard exists because transitioning was the way around the release guard — that fix is inert from the CLI. No test covers release-without-actor. |

### 3b. Structural gaps vs the field

| Gap | Who has it | Cost of not having it |
|---|---|---|
| **No structured acceptance criteria / DoD.** "`done` requires runtime evidence" is a strong rule enforced by a weak mechanism: a generic `done-unchecked` warning over ad-hoc checkboxes nothing can reason about. | Backlog.md, indexed with stable per-item indices and index-addressed mutations **[deep read]** | An agent cannot enumerate remaining criteria; a reviewer cannot diff scope against outcome; doctor cannot name which criterion is unproven. **This is the sharpest structural gap in the survey**, and it undermines the guarantee we market. |
| **No addressable body sub-regions.** The body is opaque bytes; `card write` is all-or-nothing; `card note` appends to one hardcoded `## Notes`. | Backlog.md's `SECTION:*` marker protocol **[deep read, ~45KB of TS]** | An agent replacing its plan must rewrite the whole body and risks destroying human context. Prerequisite for AC/DoD. We already own the marker machinery in `generated/managed-files.ts` — this is that concept one level down. |
| **Token economy paid up front, always.** Digest-stamped blocks in AGENTS.md/CLAUDE.md/.cursor/rules/copilot-instructions, plus a skill, plus 30 MCP tool schemas (`tools.ts` is 41 KB). | Backlog.md: 1,051-byte router stub + on-demand guides. Task Master: three named tool tiers with published token costs **[both deep read]** | Direct market evidence that users budget this. Also behavioural: a 30-tool menu makes small models pick wrong. Contradicts our own origin story (token waste). |
| **No bulk creation path anywhere.** Not CLI, not HTTP (`/cards/bulk` is patch-only), not MCP. Every card is born one `card create` at a time. | Task Master's `parse-prd` **[deep read]** | This is the funnel they won on. An agent creating 30 cards makes 30 mutations, 30 lock acquisitions, no rollback if #17 fails validation. |
| **No cross-branch awareness.** Collisions are cured after merge (`renumber`), never prevented. | Backlog.md reads task state from the git object store without checkout **[deep read]** | The most common multi-agent case — agent A moved T-0042 to `doing` on its branch, agent B on main starts the same work — is invisible until merge. |
| **No JSON contract.** `--json` ships on three surfaces with no envelope, no version, no stability statement — and the same query returns three different shapes (CLI validates the mode enum and fails hard, HTTP silently degrades, MCP silently degrades with a *different* default). | Backlog.md's versioned envelope with a written contract **[deep read]** | No way to fix the divergence without breaking unknown consumers. Precondition for any third-party ecosystem — their VS Code extension exists because the output shape was dependable. |
| **Merge semantics escalate rather than converge.** Two agents on two branches touching T-0042: git-bug produces one correct answer via deterministic replay; Beads merges cells; Workfile produces a doctor issue. | git-bug, Beads **[both deep read]** | Coherent and arguably more legible, but do not pretend Dolt buys nothing. The defensible counter is "the plan is reviewable in the same tools as the code," never "databases are bad." |
| **SPEC.md drift.** 2,175 lines naming a binary (`project`) that has not existed since the rename, specifying five commands never built, an exit code 4 never emitted, and a `DoctorRule` interface (§18.5) never implemented. Meanwhile `doctor --strict` is documented twice — including as *the* canonical CI line at :1928 — and is rejected as `CLI_ARGUMENT_UNKNOWN`. | git-bug's normative spec + committed test vectors **[deep read]** | Single biggest credibility liability for anyone evaluating seriously. git-bug's spec cannot drift because its test suite eats the spec's own testdata. |
| **Performance floor already below our own published target.** SPEC:1854 commits to a 10,000-card workspace and :1863 to "single-record mutation under 250 ms." | — | **[measured]** At 8,000 cards `card claim` reads the whole corpus *twice* before writing: ~700 ms of pure reading. Already in breach of a written promise. See §6. |
| **Dead half-designs shipped.** `recordAgentSignal` has no production caller (only `scripts/screenshots.ts` and `scripts/demo-video.ts`), so `claimState` can never return `live` or `orphaned`; `card-claim-orphaned` is unreachable; `card reap` only ever finds 24h lease expiries; the UI live-agent count is structurally 0; `/api/v2/activity` reports presence it never receives. `pruneAgentSessions` is dead too. The hook writes 54 KB of `events.jsonl` in this repo that nothing reads — and `docs/mcp.md:109` claims the UI reads it. | — | **[measured]** The README screenshots and the landing film stage a `live` state by calling an internal no shipped path calls. ADR-0006 binds published claims to the code. This is a documented-claim integrity problem, not dead code. |
| Smaller, real | | `milestone` is a free string with no record, no dates, no spelling validation. Nothing renames an `area` or a tag across a corpus — typos are permanent. No delete or uninstall anywhere (git-bug has `bug rm` / `wipe`). `archive` overloads "finished" and "was a mistake." No compaction, so Memory grows unbounded against a fixed context budget. No shell completions (17 dispatch words, ~46 subcommands, opaque `T-NNNN`). Coverage asymmetries: no `card release` over HTTP, no `memory verify` in MCP, no `card reap` outside the CLI, `card reap --dry-run` documented and refused. `ui.defaultView` is dead config read by nothing. `agents.ts:110` emits a Spanish sentence into generated agent instructions, against CONV-0001. |

## 4. Steal list

Ranked within three conviction bands. "First step" is deliberately the smallest committable action.

### High conviction

| # | What | Source | Workfile problem it solves | Cost | First concrete step |
|---|---|---|---|---|---|
| 1 | **Machine-owned body regions.** `<!-- SECTION:PLAN:BEGIN/END -->`, `AC`, `DOD`, `COMMENTS`. One tokenizer over `/<!-- (SECTION:[A-Z][A-Z0-9_]*\|COMMENTS\|AC\|DOD):(BEGIN\|END) -->/g` that pairs markers, excludes tokens inside a foreign family's range, throws on unbalanced/crossed, and rejects user values containing a marker literal. | Backlog.md | Body is all-or-nothing; `card note` appends to one hardcoded heading. Prerequisite for #2. | M (~45KB there; edge cases — stray balanced pairs in prose, markers in fenced code — are where the cost lives) | Extract the region tokenizer from `generated/managed-files.ts` into a shared module; ship `card patch --plan` as the single consumer. |
| 2 | **Acceptance criteria + DoD as indexed fields.** Serialize as `- [ ] #1 <text>` (greppable, renders on GitHub). Index-addressed mutations: `--check-ac 1 --uncheck-ac 3` repeatable and mixable. `--json` exposes `acceptanceCriteria: [{index,text,checked}]`. Project defaults in `cards.definitionOfDone`. | Backlog.md | Turns "`done` requires evidence" from a marketing line into an item-by-item mechanism. Their finalization guide states *our* philosophy — "do not check AC from code presence, grep output, or implementation intent alone" — but they have the data model to enforce it. | M | Add the two doctor rules first (`card-done-unverified-ac`, `card-ac-index-gap`) against the existing ad-hoc checkboxes; the schema follows the rules, not the reverse. Plan a deprecation path for `done-unchecked` + a baseline migration. |
| 3 | **Tiered MCP tool profiles**, orthogonal to `--read-only`. `tier: "core"\|"standard"` on each `TOOL_DEFINITIONS` entry; core ≈7 (`workspace, next, search, get_record, card_claim, card_transition, card_note`), standard ≈15, all = 30. Precedence: `mcp.tools` config < `WORKFILE_MCP_TOOLS` env < `--tools=core`. | Task Master | 30 tools charged to every session that only does next→claim→note→done. Also stops small models picking wrong tools. | S | Thread `tier` through `listMcpTools({readOnly, tier})` and both filter sites; make `mcp inspect` print per-tier counts + measured schema bytes so `docs/mcp.md:129`'s hand-written "Tools (30)" is generated, not maintained. Reject out-of-tier calls with a code naming the active profile — clients cache tool lists. |
| 4 | **`next --claim`: select and acquire in one operation.** Walk the ranked candidates; on `CARD_SCOPE_OVERLAP` advance silently to the next; return the first actually acquired. New MCP tool `project_next_claim` (`readOnlyHint: false`), not a flag on the read-only `project_next`. | Beads (`bd ready --claim`) | Two agents both run `next`, both get T-0042, one burns a full turn losing. The collision being loud is correct; making it *frequent* is not. | S | Add `--actor` to the `next` allowlist in `COMMAND_FLAGS`, then the retry loop with a bounded iteration cap. **We can do this better than Beads** — scope-path overlap means we skip to genuinely non-conflicting work rather than handing out the next id and hoping. |
| 5 | **PreCompact hook + a card-less session bundle.** `.claude/settings.json` wires SessionStart/PreToolUse/PostToolUse but not PreCompact. Point it at `agents context` with no `--card`: claims held by this actor, cards in `doing`/`review`, high-confidence LRN, active CONV, unexpired CTX. | Beads (`bd prime` on sessionStart + preCompact) | **[measured]** `workfile agents context --json` in *this* repo returns `totalAvailable: 0` and an empty `records` array — the repo that invented the protocol produces an empty session brief. `buildAgentContext` (`agents.ts:471`) never includes learnings or decisions on *any* path, so all 6 ADRs and 4 LRNs are unreachable from the command agents are told to run first. Conventions are filtered to `active`, and CONV-0001 is `draft`, so it is dropped silently. | M | Fix the bundle contents before wiring the hook — a PreCompact hook that emits an empty brief is worse than none. Include `draft` conventions with a marker rather than dropping them. Hard byte cap with a documented drop order. |
| 6 | **Structured resolutions on errors.** `ProtocolError.resolutions: Array<{description, command?}>`, rendered as a numbered list, present in `--json` and MCP `structuredContent`. | Task Master (numbered remediation on cross-tag conflicts) | Our whole coordination story is deliberate collisions. An agent that hits `CARD_CLAIM_OWNER_MISMATCH` and does not know the recovery path just stops. Messages are already drifting: `card reap --dry-run` is documented, implemented, and refused — and the refusal names `project card`, a binary that has not existed since the rename. | S | Populate the dozen codes agents actually hit. Add a test asserting every command named in a resolution string exists in the dispatch table, so they cannot rot. Do **not** offer `--force` for the ownership guard without a warning line. |
| 7 | **Bulk card import.** `card import --json-input plan.json [--dry-run] [--parent]`, plus `POST /api/v2/cards/bulk-create` and `project_card_import`. Documented plan shape with plan-local `$ref` handles resolved after allocation. Validate the whole plan before any write; reserve N ids in one pass; atomic replace; emit plan-index→card-id→path. | Task Master | The funnel they won on — **and ours can be strictly better because we refuse to do the decomposition**: the agent already has the PRD in context and produces the plan; Workfile does the part agents are bad at (id reservation, validation, all-or-nothing write, back-links). Deterministic given the same plan, reviewable as a diff. | M | Batch id reservation is a prerequisite, not a nicety — the current bounded-retry scan (max 32) was not designed for a 40-card import. Ship a `--from-markdown` front end that maps H2→epic, H3→child, `- [ ]`→checklist, **no model involved**. |
| 8 | **Progressive-disclosure agent instructions.** Shrink the managed block to a ~1KB router stating the non-negotiables (use the CLI/MCP, claim before mutating, review ≠ done), then `wf instructions [overview\|card-creation\|card-execution\|card-finalization]`, with CLI-flavored and MCP-flavored variants generated from one source. Interpolate real ids from the live project into examples. | Backlog.md | Same protocol compliance at a materially cheaper posture; also fixes that one managed block currently has to serve both CLI and tool wording. | M | Ship `wf instructions` and the MCP tool (#9) first, *then* shrink the block. Note the tradeoff: the stub's wording carries a lot of weight and the digest stops being a useful staleness signal for procedure changes — version the instruction payload separately. |
| 9 | **`project_instructions` MCP tool** mirroring the 4 resources. | Backlog.md (`get_backlog_instructions`) | Resources are the least widely supported MCP primitive and prompts are user-invoked, so in tool-only clients an agent **cannot pull our protocol brief at all**. Silent, total failure mode. | S | A few dozen lines. Generate tool and resource content from one source or they will drift. |

### Medium conviction

| # | What | Source | Problem | Cost | First step |
|---|---|---|---|---|---|
| 10 | **Versioned JSON envelope + published contract.** `{"schemaVersion":1,"kind":"card-list",...}`. Absent scalars null, absent collections `[]`, dates `YYYY-MM-DD`/RFC 3339. Internal fields, absolute paths and search scores explicitly out of contract. `--json` strictly non-interactive; errors leave stdout empty. | Backlog.md | Precondition for a third-party ecosystem, and the only way to fix the CLI/HTTP/MCP divergence without breaking unknown consumers. | M | Publish the contract document first and audit against it — the "no absolute paths" rule already conflicts with card JSON exposing `path`. Needs a major bump or an opt-in flag. |
| 11 | **Gates: typed self-resolving blockers.** Three local types only — `human`, `timer` (`now > resolve_after`), `card` (referenced card reaches terminal). `gate check` auto-resolves and prints what it released; run it from CI and SessionStart. Gated cards excluded from `next`. | Beads | `deferred` + `start`/`due` exist but nothing returns a deferred card to the ready queue when its date arrives — it is deferred until a human remembers. `blocked` has no machine-checkable exit condition. | M | The `timer` gate alone, as a frontmatter field rather than a new record kind. Leave `gh:run`/`gh:pr` resolvers to the integrations registry as a third capability — those are exactly the ADR-0006 boundary. A gate should probably *set* `blocked`, not sit beside it, or we have four ways to say the same thing. |
| 12 | **Cross-branch card state resolution** from the git object store, no checkout. Take an ID list; check current branch and main first, early-exit, batch ~5 remaining branches. `cards.checkActiveBranches` (off by default), `activeBranchDays` (30), `remoteOperations: false`. | Backlog.md | Prevention layered on our existing cure. Aimed exactly at the pain that created Workfile. | M | Gate it behind `next` and `claim` only. Costs more for us than for them — they encode lifecycle in the directory name, we parse frontmatter — so bound it hard to the candidate set and cache by commit SHA. Error messages must name which branch the conflicting state came from. `doctor` must not depend on it. |
| 13 | **Named leases.** `lease acquire <name> [--wait] [--ttl 30m]` / `release` / `list`, keyed on an arbitrary string. Surface in `/api/v2/activity`; reap with `card reap` staleness logic. | Beads (`bd merge-slot`) | Claims cover "same file." They do not cover "only one agent may rebase / run the migration / hold the dev DB." Today the only expression is a placeholder card, which pollutes the work corpus. Beads built a dedicated primitive for this in multi-agent operation — a strong signal scope claims alone are insufficient. | M (~80% exists: `.cache/locks/`, session heartbeat, `claimState`) | Ship `acquire`/`release`/`list` without `--wait`. It is a lockable entity that is not a record — no id, not indexed — and it lives in `.cache/` so it is invisible to a teammate. That is correct but must be *stated*, not discovered. |
| 14 | **Agent-mediated lossy compaction.** `compact --analyze` emits candidates as JSON for the *host agent* to summarize; `--apply --summary-file` writes them back under the normal lock + atomic replace + `expectedRevision`. Provenance in frontmatter (`compacted`, `compacted_from_bytes`, `compaction_tier`). **No `--auto`.** | Beads (`bd compact`) | Archive is lossless and Memory is unbounded; `agents context` has a fixed budget and a growing corpus. The only shipped answer in the field. | L | The `--analyze`/`--apply` split is what preserves "Workfile never sends repository content to a network service by itself" verbatim — it is the same shape as the injected semantic-search provider. Refuse to compact anything reopenable; only `archived` and terminal Memory. Restate the codec guarantee as "preserved unless you invoke a lossy op." |
| 15 | **Shell completions** with live project values — real card ids for `card show <TAB>`, configured areas/statuses for `--area`/`--status`. | Backlog.md | 17 dispatch words, ~46 subcommands, per-command flag allowlists, opaque `T-NNNN`. Difference between the CLI being usable by the human next to the agent and being agent-only. | M | **The refactor is the value**: extract a declarative command registry from the hand-maintained `GLOBAL_FLAGS`/`COMMAND_FLAGS` constants. The same registry fixes help text, docs generation (`docs/cli.md` omits `card note`, `card write`, `version`, the whole `claude` group), and per-subcommand flag validation (#18). |
| 16 | **Referential-integrity rename/delete for shared strings.** `milestone rename <old> <new>` rewriting every referencing card in one locked transaction; `milestone remove --task-handling clear\|keep\|reassign` with a **required** policy, no silent default. | Backlog.md | The transferable mechanic is not "add a milestone record" — it is *rename cascades, delete demands a policy*. We have the same latent problem for `area` and tags: nothing renames an area, so areas are effectively immutable and typos are permanent. | M | Start with tags (no config coupling). A cascading rename collides with per-record locks and claim ownership — document the answer (skip-and-report vs `--force`) before writing code. Renaming an `area` means editing `project.config.mjs` in the same transaction, which we never do today. |
| 17 | **Dependency closure as an explicit operand.** `depends-closure:T-0042` / `blocks-closure:T-0042` grammar terms, plus mutually exclusive `--with-dependencies` / `--ignore-dependencies` on `card archive` and `transition --status deferred\|discarded`, where omitting both is a **hard refusal** listing the closure it found. | Task Master | Deferring an epic silently strands its blockers in `next`. No query answers "what does this card actually need" without N `card show` calls. ## 5. Original ideas

Six things that exist in none of the four competitors, each enabled by something specific in our data model. Counterargument stated in full, because these are the ones most likely to be wrong.

### 5.1 Evidence as a typed record, not prose

`done` requires runtime evidence. Make evidence structured: `evidence: [{kind: test|command|url|commit|screenshot, ref, exit_code, captured_at, digest}]`. Doctor then checks what is checkable — the referenced commit exists in this repo, the named test file exists, the URL is well-formed, the digest matches a file still present. `agents context` returns prior evidence shapes for the area so an agent knows what "proven" looks like here.

*Enabled by:* nobody else has the requirement at all, so nobody has a reason to type it. Beads and Backlog.md let a status string be set by anyone; Task Master's `testStrategy` is planning-time intent, not outcome.

**Strongest counterargument:** you cannot verify that evidence is *truthful*. An agent can fabricate an exit code as easily as it can write a paragraph. Schematising the field converts a social contract into a checkbox and may create false confidence that is worse than the honest ambiguity. The only real verification requires *running* things, which the tool refuses to do. Rebuttal, partial: the checkable subset (commit exists, file exists, digest matches) is small but non-empty, and the value is less in verification than in making evidence *diffable* and *enumerable* — a reviewer can see three cards closed with no evidence at all.

### 5.2 Scope-aware dispatch: rank `next` for disjointness, not just priority

`rankNextCards` orders by priority and readiness. Because claims declare *scope paths*, `next` can additionally rank candidates by non-overlap with currently-held claims, so N concurrent agents receive N disjoint work fronts by construction rather than by collision-and-retry. Combined with #4 (`next --claim`), a swarm converges on a partition of the repo instead of contending for its centre.

*Enabled by:* claim granularity below the issue. Beads cannot do this — it claims issues and has no file-level knowledge, so it cannot tell whether two ready issues touch the same code.

**Strongest counterargument:** greedy disjointness starves important work. The highest-priority card is frequently in the most contended part of the repo (the core module everyone is touching), and a disjointness ranking systematically defers exactly that card in favour of peripheral work that happens to be free. You would ship a scheduler whose bias is invisible in the output — the agent gets a card and has no idea it got the *available* one rather than the *important* one. Mitigation would be a hard rule that priority dominates and disjointness only breaks ties, which reduces the idea to a tiebreaker and most of its value with it.

### 5.3 Field-level record history reconstructed from git blobs

Records have stable ids, stable paths, and a byte-stable frontmatter codec whose parser and serializer are exact inverses. That makes it possible to reconstruct, deterministically, the *field-level* timeline of any record: `wf log T-0042` showing every status transition, every claim, every priority change, with commit, author and date — parsed, not scraped, because the codec can parse any historical revision of the file exactly as it parses the current one. Add a `history:` grammar term (`status:done history:blocked` — cards that were once blocked).

*Enabled by:* stable paths + a total codec. Backlog.md forfeits this — filenames carry the title, so a retitle is a rename that breaks blame continuity. Beads' history is in Dolt and invisible to git tooling. git-bug has an operation log but no cross-domain query over it.

**Strongest counterargument:** we have a stated boundary of not owning git, and this makes git a hard dependency of a read path. Cost is also real: `git log --follow` per record, then parse N historical blobs — and the archive move *is* a rename, so `--follow` is mandatory and fragile. Worse, the `## Activity` trail already answers most of this question in-band, durably, without shelling out. This may be a solution looking for the question the trail already answered.

### 5.4 Cross-domain closure: a card is not done until the changelog says so

We have four domains on one index and use exactly none of the cross-domain integrity that buys. Make it real: `card transition --status done` optionally requires (config-gated) at least one `CHG` fragment referencing the card, and `changelog release` refuses to consume a fragment whose referenced cards are not terminal. A `card-done-no-fragment` doctor rule and a `fragment-references-open-card` rule.

*Enabled by:* the shared `ProjectRecord` index. Beads has no History domain; Backlog.md has no changelog; Task Master has neither.

**Strongest counterargument:** it couples two domains people legitimately use independently, and it is wrong on its face for most cards — refactors, spikes, chores and internal cards produce no user-visible change and should produce no fragment. The `visibility` field on fragments exists precisely because not everything is public. Making this a gate adds friction to the fastest path in the tool in exchange for tidiness. It is defensible only as an opt-in doctor rule (`warning`, baselined), never as a transition gate — at which point it is a small feature, not an original idea.

### 5.5 Baseline waivers that expire

`doctor --accept-baseline` mutes existing issues so a repo can adopt the gate without drowning. Today that mute is permanent and undated. Because Memory has typed collections with *expiry* (CTX) and *supersession*, each baseline entry can become a CTX record with an `expires` date and a reason. Muted debt re-fires on a schedule instead of being silently forgiven, and `wf memory list --collection context` becomes the honest register of what we agreed to ignore and until when.

*Enabled by:* CTX expiry as a first-class concept, which exists nowhere else in the field.

**Strongest counterargument:** the baseline exists so a team can move on. Adding a timer converts a mute button into a nag nobody scheduled, and the predictable outcome is that everyone sets `expires` to 2099 or re-accepts the baseline wholesale — at which point you have added a field, a rule, and a ritual for nothing. It also mixes a health-subsystem concern into a knowledge domain, which is exactly the kind of coupling §5.4's counterargument warns against.

### 5.6 A conformance report for the agent, not the repo

`doctor` validates the repository. Nothing validates the *agent's* behaviour, even though the data to do it is already written: claims, the activity trail, evidence, and (once wired) the session ledger. `wf agents report --since 7d` could compute, per actor: mutations made while holding a claim vs without, claims released vs abandoned, cards moved to `done` with and without evidence, cards created for discovered work, average time from claim to release. This is the only surface in the field that could answer "is this agent following the protocol" with data rather than vibes.

*Enabled by:* actor-stamped mutations plus enforced claims. No competitor stamps mutations with an actor at all.

**Strongest counterargument:** it is a metrics surface, which is scope creep away from a protocol, and metrics on agent behaviour will be gamed the moment they matter — an agent optimising "cards created for discovered work" spams the backlog, which is the exact failure Backlog.md wrote a rule to prevent. It also requires the identity fix to be true first (§3a), and its most useful number — evidence quality — is precisely the one §5.1's counterargument says cannot be measured. File it, do not build it, until identity is fixed and someone actually asks the question.

## 8. Flows

### The loop today, and where it breaks

```
SessionStart hook
  └─ agents context ......................... returns 0 records in THIS repo [measured]
next .......................................  heuristic; no scope-disjointness
claim ......................................  actor = $USER@$HOSTNAME (CLAUDE_SESSION_ID is a phantom)
  └─ MCP claim in the same session .........  actor = mcp:<clientName>   ← different string
edit
  └─ PreToolUse guard .....................   compares a UUID to an actor name → ASKS ON YOUR OWN CARD
note
transition review ..........................  no --actor default → ownership guard silently skipped
done (requires evidence) ...................  evidence is prose; doctor cannot name what is unproven
changelog fragment .........................  entirely manual, decoupled from the card
doctor .....................................  works, and is the best thing in the loop
```

Every arrow marked with a break is a bug, not a design gap. The protocol is sound; three of its four enforcement points are not connected.

### The loop to build toward

1. **One identity, resolved once.** `resolveActor()` in a shared module: `$WORKFILE_ACTOR` → `cards.actor` → `CLAUDE_CODE_SESSION_ID` (as a *ledger key*, never as `claimed_by`) → `$USER@$HOSTNAME`. One format. Three call sites. `workfile agents whoami` prints the resolved actor and which rung produced it — with a `USAGE.agents` line and a `docs/cli.md` entry in the same change, per LRN-0004 (a command without a usage line does not exist for agent callers).

   **Do not** put the session id first in the durable actor. That would stamp a fresh UUID into git-committed frontmatter and recreate exactly the `agent-56a30d1b` pattern `defaultActor()`'s own comment exists to kill.

2. **The session ledger gets a producer.** `card claim` writes `{sessionId, actor, cardId}` via the already-built `recordAgentSignal`; the hook writes it inline (~20 lines, not an import — the 30 ms p95 budget is pinned by a test); `pruneAgentSessions` (also dead) runs at session start or the files accumulate exactly as `events.jsonl` did. Drop "every CLI mutation refreshes the heartbeat" — a process that exits cannot heartbeat, and a 90-second-stale file would flip healthy cards to `orphaned`.

3. **Selection and acquisition collapse.** `next --claim` returns work the agent actually holds, skipping scope-contended candidates rather than failing.

4. **The brief is bounded and non-empty**, served at SessionStart *and* PreCompact, containing decisions and learnings (which it never contains today, on any path).

5. **Procedure is pulled, not pushed.** A ~1KB router stub; `wf instructions card-finalization` at the moment of finalization; the same content reachable as an MCP *tool*, not only a resource.

6. **Finalization is enumerable.** `wf card ac T-0042` lists what is unproven. `transition --status done` with unchecked AC is a doctor error, not a vibe. `--force` exists and is documented, with the actor default, so `/done` has an escape rather than a wall.

7. **Discovered work: synthesise, do not import.** Backlog.md forbids agents from creating follow-up work unprompted; that directly contradicts our standing instruction to create cards for discovered work. Their rule exists because unsupervised agents spam the backlog — a failure we will hit too. The synthesis: **agents create discovered-work cards freely, constrained to `backlog` status, and are forbidden from starting them.** Constrain the status, not the record.

### The human loop

Unchanged and mostly fine: Overview as "what happened while I was away" (add the watermark), Inspector as the write surface, `doctor --new` as the gate, `board export` (#27) for reviewers who will never run the UI. The one thing the human loop needs that it does not have is the ability to trust that `claimed_by` means something — which is item 1.

It fails on its own headline gap (module *totals* don't change when a DOC is edited, so the row never fires for the most common non-card write) while discarding `change.paths`, which already contains the exact path. Degrades to nothing under the polling fallback — i.e. absent precisely on the network filesystems polling exists for — and under `VITE_DEMO=1`, so the hosted demo can never show it. | Two narrow real things: the trail cannot say which rows are new since you last looked, and a foreign write is silent on Explorer/Flow/Triage. Both are cheap (§7 items 3–4). |

### Competitor mechanics deliberately not copied

| Mechanic | Who | Why not |
|---|---|---|
| **User-configurable status strings** | Backlog.md, Beads | Their `config.yml` reads `statuses: ["To Do","In Progress","Done"]`, and the cost is visible in their own shipped agent guides: they cannot *name* a status anywhere, so every instruction says `-s "<active status>"` and tells the agent to run `--help` to discover the real values. Our fixed 8-status enum is why our guidance can say `review` and mean it. Do not soften this under user pressure. `areas`, `tags`, doc kinds and memory collections are already configurable — that is the right amount of give. |
| **Filenames carrying the title** | Backlog.md | Beautifully greppable; every retitle becomes a rename + content change, breaking blame, permalinks, open tabs and bookmarks, and making path-length limits a live hazard. |
| **Encoding hierarchy in the ID** (`back-355.02`) + migratable prefixes | Backlog.md, Beads | Produced the exact failure observed: a task whose id reads `BACK-200` while its dependencies reference pre-migration `task-24.1`. The maintenance bill is a 27KB `duplicate-task-repair.ts` and a `task-identity-index.ts`. Flat immutable `T-NNNN` + a separate `parent` field is correct. |
| **Hash IDs** (`bd-a1b2`) | Beads | A real tradeoff, not a mistake: collision-free by construction, and unsortable, unmemorable, unsayable in a standup. `T-0042` costs a reservation lock and a heal path; that buys an id a human can type from memory. Keep paying it. |
| **Per-record shell hooks** | Backlog.md (`onStatusChange` frontmatter override) | A card file arriving via a pull request can execute arbitrary shell on the maintainer's machine when anyone changes its status. That is RCE with a task tracker as delivery. Take the config-level hook only — `project.config.mjs` is already executable JS we import, so no new trust boundary — and explicitly refuse the frontmatter override. **Record files must never be executable inputs.** |
| **`autoCommit` / `bypassGitHooks`** | Backlog.md | `bypassGitHooks` exists to pass `--no-verify` so the tool's own commits skip the user's pre-commit hooks. Our entire doctor value proposition is *being* that gate. |
| **Full YAML frontmatter** | Backlog.md | Block sequences, quoted scalars, a configurable datetime format with a backfill migration. Adopting real YAML forfeits byte-stable round-tripping and unknown-field preservation permanently, for expressiveness a restricted schema does not need. |
| **Fuzzy-only search** | Backlog.md | Friendlier to type, non-deterministic to reason about, cannot express structured intent. Add fuzziness as an explicit opt-in mode, never the default. |
| **Interactive-by-default commands** | Backlog.md | `backlog task 7` opens a TUI; they had to write the rule "explicit JSON mode is always noninteractive, including in a terminal" because TTY detection kept surprising callers. If `wf board` ever ships, make it a static ANSI render safe in CI. |
| **Convention-based multi-agent coordination** | Backlog.md | File locking around ID allocation plus "one task = one context window = one PR". Take the role-detection *hint*; leave the rest. |
| **Stealth mode as a named feature** | Beads (`bd init --stealth`) | A mode whose purpose is that protocol data does *not* live in the repository contradicts "repository-native" in our first sentence. `--root` covers the mechanical need. |
| **Vocabulary sprawl** | Beads (rigs, polecats, molecules, convoys, formulas, aspects, expansions, swarms, ~30 command groups) | You must learn a world before you can file a task. We have 17 dispatch words and documented coverage asymmetries between CLI/HTTP/MCP. Close those before adding nouns. Test every steal-list item against "does this need a new word, or can it be a flag on a word that exists." |

## 10. If you only do three things

All three are bugs. That is the finding, not an evasion: **the two guarantees the README sells as the differentiators are both false in the shipped default configuration**, and no feature on the steal list matters until they are true, because they *are* the positioning. Backlog.md, Beads and Task Master will each out-ship us on features. None of them can claim enforced multi-agent safety — unless ours does not work.

### 1. One resolved actor identity, and close the two ownership holes

**Cost: S.** `resolveActor()` in one module, read by `bin/workfile.ts:614`, `mcp/tools.ts:105` and `runtime/claude/hooks.mjs:126` (+ regenerate the plugin mirror). Delete the `CLAUDE_SESSION_ID` branch rather than renaming it — session ids are the ledger key, never the durable `claimed_by`. Add `|| defaultActor()` to `release` (`:917`) and `transition` (`:933`) **in the same commit** that wires `force: has("--force")` into `transitionCard` and documents it in `USAGE.card` — shipping the default alone turns a silent force into an unescapable wall for `/done`.

**Why first:** it is the smallest of the three and everything downstream depends on it. Today the guard rail asks on your own card *and* stays silent between two parallel sessions — false in both directions simultaneously. `claim:me`, saved views, `next --claim`, the session ledger, `card reap`'s orphan branch and the UI's live count are all blocked on identity being one string. Acceptance test: two processes with different `CLAUDE_CODE_SESSION_ID` values in one checkout must produce `CARD_ALREADY_CLAIMED`. Today they do not. Also add the mirror case to `test/claude-surface.test.ts:145`, which only ever exercises *another* actor's scope — that hole is why this shipped.

### 2. Fix the ID reservation race, and ship the test at S scale

**Cost: S** (four files, one restructure in `changelog.ts`). Re-verify the id inside the held reservation with a domain-complete directory listing — recursive for docs — then `createFileExclusive`.

**Why second:** it is the other published guarantee ("collision-safe ID reservation," README:652), it is the *only* one of the three that produces corrupt data rather than degraded behaviour, and the repo carries a written belief that it does not exist (T-0019: "same-checkout races are already handled"). Measured at 200 cards / 4 concurrent agents — a mundane session in this project's own daily operating mode. Second rather than first only because it shares `mutations.ts` with item 1 and both should land in one sequence, and because item 1's identity fix is a prerequisite for the concurrency test to assert anything meaningful about *who* won. Correct T-0019 with an INC carrying the measured rates, and annotate `test/cards.test.ts:124` — it structurally cannot catch this and will otherwise be re-trusted.

### 3. Stop discarding the search postings, and stop loading the corpus twice

**Cost: XS.** `search.ts:183` — skip the filter when no kinds are requested. `mutations.ts` — four one-line `snapshot` passes in `claimCard`/`releaseCard`/`transitionCard`/`archiveCard`.

**Why third:** the cheapest item on the list by an order of magnitude, ~45× on the CLI's real search path at L (96 ms → 2 ms, including for queries that match nothing) and a free 2× on the four most-used mutations at *every* scale. It is third and not first only because it makes a working tool faster while 1 and 2 make a broken guarantee true. Gate it with a body-read-counting test in the style `test/budgets.test.ts` already established.

**Then, and only then**, the first feature: **tiered MCP tool profiles** (S, §4 #3) followed by **body regions → acceptance criteria** (§4 #1–2), because AC is the sharpest structural gap in the survey and it is the mechanism that makes "`done` requires runtime evidence" — the thing we market — actually enforceable item by item.
