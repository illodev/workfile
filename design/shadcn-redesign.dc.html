Un solo motor de consulta para las cuatro superficies

.project/cards/T-0091-un-solo-motor-de-consulta-para-las-cuatro-superfic.md

Cards, docs, changelog y memory resuelven filtros, orden y paginación cada una a su manera: el CLI filtra en memoria después de leer el directorio entero, la API v2 acepta parámetros que el índice ignora y la UI vuelve a filtrar en el cliente. La misma consulta devuelve tres resultados distintos según por dónde entres.

Un motor único sobre ProjectRecord con el contrato de lista compartido: mismos operadores, mismo orden estable, misma proyección de campos.

Cada decisión escribe el frontmatter de la card en disco al instante. El atajo funciona mientras el foco esté fuera de un formulario.

El circuito

  1. Cortar el changelog: workfile changelog release <version> y render --write.
  2. Versionar y etiquetar: npm version <version>, luego git push --tags.
  3. El workflow verifica que el tag coincide con package.json, ejecuta check:release y publica por OIDC.

Las prereleases van al dist-tag next; las estables a latest. No hay token de npm en el repositorio.
